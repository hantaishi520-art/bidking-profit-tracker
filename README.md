> ## 📌 使用说明（解析器 v2.34）
> `BidKing解析器.exe` 与 Python 脚本两种方式均可正常解析，按你的使用习惯选择其一即可：
> 1. **富界面（拖文件）**：运行 `python src/serve.py`，浏览器打开提示地址里的 `bidking_standalone.html`，把 `Player.log` 拖进去即可。已内置完整物品价格表（含竞拍之巅）与道具名称；报表与独立解析器均已加入「竞拍之巅」地图筛选（5601-5611，门票 15000）。
> 2. **命令行生成结果**：运行 `python src/run_parser.py`，自动读取游戏默认日志并生成 `result.json`，再用 `python src/serve.py` 打开 `bidking_report.html` 查看富报表。
>
> ### 解析要点：双数据源合并
> 日志里对局记录分布在两处，**任何单一来源都不完整**：
> - `S2C_89`（`S2C_89_get_game_log_list`）：历史总览列表，覆盖你之前玩过的全部对局（可能是一份滚动快照，会滞后于刚结束的局）。
> - `S2C45`（`S2C_45_game_over_notify`）：每局结束时的实时结果通知，包含**刚结束、还没进历史快照的最新几局**。
>
> 解析器**两者都读并去重合并**，得到完整对局集（实测当前日志已合并出 56 场，且随游玩持续增长）。
> 已用 v2.33 官方 `BidKing解析器.exe` 对 `S2C45` 的最新两局做真值比对，**盈亏数值逐字段完全一致**。
>
> ### 注意日志是实时增长的
> `Player.log` 在你游玩时会持续写入。若想看最新战绩，玩完一局后**重新运行 `run_parser.py`（或把最新日志拖入独立解析器）** 再打开报表即可。解析器会自动识别你的 UID（出现最多的玩家）。

## 免环境 EXE 用法

> 说明：双击 `BidKing解析器.exe` 即可一键使用，无需安装 Python。以下为 EXE 用法说明。

1. 双击运行 `BidKing解析器.exe`。
2. 程序会启动本地可视化服务，并自动打开 `bidking_report.html`。
3. 如果页面里显示的 UID 不是自己，可以在 `玩家 UID` 输入框手动输入；也可以点击 `从日志读取 UID`，从日志里选择候选玩家。
4. 在网页中点击 `实时刷新`。
5. EXE 会自动按顺序查找日志：
   - 当前运行目录下的 `Player.log`
   - `BidKing解析器.exe` 同目录下的 `Player.log`
   - 游戏默认日志：`C:\Users\你的用户名\AppData\LocalLow\laolin\BidKing\Player.log`
6. 每次点击 `实时刷新` 都会先删除同目录旧的 `result.json`，再生成新的 `result.json`。
7. 网页会自动读取最新 `result.json` 并刷新统计，不需要手动拖入文件。

> 注意：请通过 `BidKing解析器.exe` 打开网页。普通双击 `bidking_report.html` 时，浏览器不能直接执行 EXE，只能手动选择 JSON。
> 如果更新后有人仍看到旧界面，请确认是从 EXE 打开的地址。EXE 会自动给页面附加 `html_cache` 版本号，并对 HTML/JSON 响应禁用浏览器缓存。

这个工具要给「零安全意识」的用户用，安全设定是**默认就安全、不依赖用户懂安全**；同时按需求分级——**同一 Wi-Fi 局域网视同本机信任，严苛防护只针对 ngrok 公网**：

## 命令行用法（推荐）

需要本机已安装 Python 3.10+。全部文件已自带，无需联网或额外安装。

**方式 A — 一键生成结果（最省事）：**

```powershell
python src/run_parser.py
```

自动读取游戏默认日志 `C:\Users\<用户名>\AppData\LocalLow\laolin\BidKing\Player.log`，
自动识别你的玩家 UID，生成 `result.json`。

**方式 B — 手动指定参数：**

```powershell
python src/bidking_parser.py "<Player.log路径>" auto src/item_prices.csv result.json
```

- 第 2 个参数填 `auto` 会自动选日志中出现最多的玩家（即你自己）；
  也可直接填你的 UID（如 `123456789012345`，在网页顶部的「玩家 UID」处能看到自己的）。
- 第 3 个参数为物品价格表 `item_prices.csv`（已附带，来自 v2.33 最新价格表）。
- 第 4 个参数为输出文件 `result.json`。

**方式 C — 打开富报表 / 独立解析器（必须走本地服务器）：**

```powershell
python src/serve.py          # 默认 8000 端口，可加端口号：python src/serve.py 8123
```

启动后浏览器访问：

- 富报表：`http://localhost:8766/bidking_report.html`
- 独立解析器（拖文件）：`http://localhost:8766/bidking_standalone.html`

> 注意：直接双击 html 用 `file://` 打开时，浏览器会拦截 `fetch('result.json')`，
> 因此务必通过 `serve.py` 提供的本地地址打开。

## 注意事项

- 需要在另一台电脑查看时，先在运行游戏/日志的电脑上双击 `BidKing解析器.exe`。页面顶部会显示 `另一台电脑访问：...`，同一局域网内的另一台电脑用浏览器打开这个地址即可。
- 如果另一台电脑打不开，请确认两台电脑在同一个 Wi-Fi/局域网，并在运行日志解析器的电脑上允许 Windows 防火墙放行 `BidKing解析器.exe` 或端口 `8766`。
- 不要删除 `bidking_standalone.html`，否则物品价值和地图名称可能不完整。
- `Player.log` 很大也没关系，解析器会逐行读取，不会像浏览器版本那样一次性载入整个日志。
- 后台异步刷新解决的是页面等待问题；日志本身仍然需要读取，文件越大解析时间越长。
- 如果游戏正在运行，`Player.log` 可能还在增长；需要稳定结果时，建议先退出游戏再运行解析器。
- 如果自动查找失败，可以把 `Player.log` 放到 `BidKing解析器.exe` 同目录后再运行。
- **⚠️ 报表显示 0 局，不代表你没打过**：解析器只读当前的 `Player.log`，而游戏一重启就会把旧日志改名存档（`<uid>_<时间>.txt`）。所以新会话还没打过拍卖时，报表会显示 0 局或局数突然变少。
  - **你的完整战绩在 `生涯数据库/career.db` 里**（永久累积，不会丢）。想看历史请打开「生涯」页。
  - 局数变少时程序会自动备份旧的 `result.json`，并按提示让你选择是否保留。
