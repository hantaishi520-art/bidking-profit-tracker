# 游戏更新藏品采集流程（UnityPy 挖表 → 落库 → 重打）

> 用途：BidKing 游戏热更后，把「新增藏品 / 价格变动」同步进工具的三份内置表。
> 2026-09-03 首次完整跑通（一次挖出 50 个新藏品、修正 74 处价格）。
> 方法要点已收录于 `docs/防踩坑指南.md` 测7（挖表）与测8（BOM 坑），本文件是全流程展开版。

## 前置条件

- 游戏已更新（热更资源已下载到本地 Steam 目录）
- Python 3.10+，装有 `UnityPy` 与 `lz4`（首次：`pip install UnityPy lz4`）
- 游戏安装目录（路径按本机情况填，例如 `D:\Steam\steamapps\common\BidKing`）

## 一、定位游戏资源

热更资源在游戏目录下：

```
<游戏目录>\BidKing_Data\StreamingAssets\yoo\
```

物品配置表在 `DefaultPackage` 系列 bundle 中，按内部名识别：

```
defaultpackage_assets_game_bundle_tables.bundle   ← 全套配置表（约 3.5MB，同类 bundle 有 7 个，文件名哈希无规律）
```

**关键认知**：bundle 是 LZ4 压缩块，**明文 grep 搜不到任何物品名/价格**——必须解包。日志（`S2C45` 拍品 `StockBoxes` / `E_OnGameOver`）只带 `Cid/Quality`，不带名称与价格，这就是「日志里拿不到、必须挖表」的根本原因。

## 二、UnityPy 解包 Item 表

```python
# 解包 Item 表（TSV）→ 输出到临时文件 _tmp_Item.txt（用完即删）
import UnityPy, os

bundle = r"<游戏目录>\BidKing_Data\StreamingAssets\yoo\DefaultPackage\defaultpackage_assets_game_bundle_tables.bundle"
env = UnityPy.load(bundle)
out = []
for obj in env.objects:
    if obj.type.name == "TextAsset":
        if obj.read().name == "Item":          # 物品配置表
            out.append(obj.read().script.decode("utf-8"))
            break
data = "\n".join(out)
open("_tmp_Item.txt", "w", encoding="utf-8").write(data)
print("行数:", len(data.splitlines()))
```

> 提示：若找不到该内部名，先 `UnityPy.load(bundle)` 遍历 `TextAsset` 打印所有名字（有 `Item / Item_Type / Item_WareHouse / BidMap / Language` 等全套表）。

## 三、列映射与锚点验证

`Item` 表为 TSV，每行一个物品，关键列（已用 1916045 鲁班锁积木锚点验证）：

| 列索引 | 含义 | 示例（1916045） |
|---|---|---|
| [0] | cid | 1916045 |
| [1] | 名称 | 鲁班锁积木 |
| [6] | category_tags（类别） | [101] |
| [7] | shape | 11 |
| [8] | quality | 6 |
| [9] | **base_value（基础价格）** | 80600 ✓ 与用户提供价吻合 |
| [15] | grid_size | [10,5] |

**先验锚点**：拿一个已知藏品（如 1916045=80600）对第 10 列（索引 9），吻合再继续，防止列序理解错误。

## 四、对比判定：新增 vs 价格变动

工具现有表 = `src/item_prices.csv` ∪ `src/v233_items.json`（合并后约 1253 条）。

判定逻辑：

- **新增**：游戏表有、工具表没有，且 category_tags ∈ {100, 101…111}（藏品类）且价格 > 0 → 落库
  - ⚠️ 排除道具类：[4]/[5]（宝箱）、[12]-[19]（头像/勋章/皮肤/称号等）——如 220006「青龙宝箱」、250027「称号箱」虽带价格，但**不是可拍卖藏品**，不入表（工具惯例只收 100-112）
- **改价**：两边都有、价格不同 → 按游戏表刷新（2026-09-03 一次 74 处：万象藏品全线减半、专家箱 -1/3、生肖 8000→8888、金币 1000→2500）
- **处理但不动**：工具表有、游戏表已无 → 保留（历史数据/生涯引用）；`item_prices.db`（用户自定义层）→ **永不自动覆盖（红线）**

## 五、落库（三处必须同步刷）

| 文件 | 格式 | 注意 |
|---|---|---|
| `src/item_prices.csv` | 7 列：item_id,name,category_tags,shape,quality,base_value,grid_size | **无 BOM（utf-8）**；多标签 category_tags（含逗号，如 `[101,106]`）**必须带引号** |
| `src/v233_items.json` | 单行紧凑 `{"cid":{"n":名,"p":价},...}`，`separators=(",",":")` | JS/解析共用名称表 |
| `src/bidking_standalone.html` | 内嵌 `var ITEMS={"cid":{"n":名,"p":价},...};`（单行） | 拖文件模式的价格源，**最易漏刷** |

> ⚠️ **BOM 坑（测8，真实踩过）**：CSV 写回用 `utf-8-sig` 会带 BOM，而 `bidking_parser._build_item_table()` 用 `utf-8` 读 → 表头第一列变 `\ufeffitem_id` → 真实解析 `KeyError`。**写 CSV 一律用 `encoding="utf-8"`**；校验也**必须用 utf-8（不是 sig）读一遍**（校验脚本用宽松编码全绿、生产用严格编码炸，是最典型盲区）。

另外注意：`bidking_report.html` / `bidking_item_prices.html` **不内嵌价格表**（报表读 result.json 解析结果、价格管理页走接口），不用刷。
